# Configuration guide by example

Each folder here is one lesson: a `vfl.toml`, a `before` file, the `after` file vfl makes
of it, and a README explaining the settings. Run the command of the README in the folder
and compare the result with `after`, or just diff the two files. Every key is described in
[configuration.md](../../docs/configuration.md) and every rule in
[lints.md](../../docs/lints.md).

The `after` files and the lint findings are generated by vfl itself, and a test
(`crates/vfl-cli/tests/examples.rs`) fails when they drift from what vfl does.

## Linting (`vfl lint`)

| Example | Shows |
|---------|-------|
| [01-presets-and-levels](lint/01-presets-and-levels) | `preset`, rule levels and options. |
| [02-safe-fixes](lint/02-safe-fixes) | `vfl lint --fix`. |
| [03-unsafe-fixes](lint/03-unsafe-fixes) | `vfl lint --fix --unsafe-fixes`. |
| [04-naming](lint/04-naming) | `naming/*` conventions. |
| [05-suppressions](lint/05-suppressions) | `-- vfl-ignore` and `-- vfl-ignore-file` comments. |

The lint examples have a `findings.txt` with what `vfl lint before.vhd --output-format
concise` reports. Their `vfl.toml` excludes `after.vhd` from the project only so that the
two copies of the same entities do not clash.

## Updating

After a change to vfl that changes an `after` file or the findings:

```sh
VFL_BLESS=1 cargo test -p vfl-cli --test examples
```

then check the diff. To add an example, make a folder with a `vfl.toml`, a `before` file
and a README, list it in `EXAMPLES` in `crates/vfl-cli/tests/examples.rs` and in the tables
above, and run the command above.
